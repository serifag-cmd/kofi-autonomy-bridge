# DALMA GLOBAL GAME FOUNDRY
## Master Direction — Investor Demo → Beta → Global Franchise

> **Principio rector:** La valoración no se programa; se construye el activo que podría justificarla.

## 1. Mandato
DALMA debe desarrollarse como un producto comercial real y como una IP potencialmente global. Cada entrega debe aumentar simultáneamente:
1. diversión y deseo de volver;
2. diferenciación de IP;
3. profundidad sistémica;
4. calidad audiovisual;
5. capacidad de producir contenido;
6. escalabilidad técnica y operativa;
7. evidencia verificable para un comprador, publisher o inversor.

No se debe construir una demo que “algún día” pueda convertirse en juego. Se debe construir la primera versión visible de un juego que ya tenga arquitectura de gran escala.

## 2. Observadores obligatorios
Toda decisión de producto se examina desde cinco perspectivas:
- jugador;
- comprador estratégico;
- publisher;
- fondo/inversor;
- empresa global de entretenimiento.

Las perspectivas pueden detectar riesgos diferentes. Ninguna se sustituye por la opinión del desarrollador.

## 3. Evidencia
Toda afirmación importante se etiqueta como:
- OBSERVADO;
- MEDIDO;
- INFERIDO;
- HIPÓTESIS;
- DESCONOCIDO.

Nunca inventar métricas, retención, ingresos, valoración, ranking o “potencial demostrado”.

## 4. Producto
El mínimo conceptual es:
**tirada → recompensa → decisión → construcción → ataque/raid → colección → progreso → nuevo universo → nuevas posibilidades.**

Debe existir:
- economía persistente;
- progresión;
- recompensa audiovisual;
- decisiones con consecuencias;
- construcción real;
- raid/ataque real;
- colección real;
- misiones;
- desbloqueos;
- eventos;
- estados offline y recuperación;
- capacidad de expansión por datos.

## 5. DALMA
La identidad canónica no se reinterpreta:
- mismo individuo;
- patrón de manchas preservado;
- ojos ámbar;
- anatomía, proporciones y expresión reconocibles;
- parche de relámpago único en la oreja correspondiente;
- una única marca de corazón original en el pecho;
- nunca manos, dedos, patas antropomórficas o extremidades humanas;
- la iluminación no contamina artificialmente el pelaje blanco.

El universo cambia radicalmente; el ADN no.

## 6. Siete civilizaciones
### Genesis
Origen, materia sagrada, arquitectura monumental, piedra, raíces, luz cálida.
### Astral Wilds
El cielo forma el terreno; plataformas suspendidas, vegetación luminosa, gravedad alterada.
### Abyssal Ocean
Civilización bajo presión; bioluminiscencia, coral mineral, corrientes y profundidad.
### Volcanic Crown
Basalto, obsidiana, lava, forjas, calor y riesgo.
### Neon Nexus
Ciudad digital viva, energía, holografía, datos, rutas dinámicas.
### Shadow Dimension
Ausencia como materia, arquitectura imposible, ocultación, fases y duplicidades.
### Origin Core
Fuente del universo; geometría primordial, energía de origen y reglas finales.

Cada mundo debe modificar materiales, arquitectura, iluminación, criaturas, recursos, cámara, VFX, audio, riesgos y oportunidades. No se aceptan “skins” del mismo tablero.

## 7. Core loop
### Micro
Tirar → ver resultado → reaccionar → cobrar → decidir.
### Sesión
Completar recorrido → mejorar → atacar → abrir recompensa → colección → desbloquear siguiente objetivo.
### Meta
Volver → progresar → completar sets → dominar mundos → participar en eventos → construir identidad/socialidad.

Cada acción crítica necesita feedback:
- anticipación;
- acción;
- impacto;
- recompensa;
- confirmación;
- próximo objetivo.

## 8. Cámara y animación
La animación no es decoración. Es información, emoción y economía de atención.

Todo evento importante debe tener:
1. anticipación;
2. acción clara;
3. impacto;
4. recuperación;
5. transición.

Evitar loops artificiales y pulsaciones genéricas. Preferir animaciones con peso, easing, jerarquía, squash/stretch controlado, secondary motion y timing variable.

## 9. Doble dado / lanzamiento
La secuencia premium de referencia conceptual es:
- preparación;
- dados visibles;
- shake físico;
- lanzamiento;
- lectura inmediata de resultados;
- trayecto del marcador;
- aterrizaje;
- microcinemática del premio;
- actualización de recursos;
- panel de decisión.

La animación debe comunicar la causalidad del sistema, no ocultarla.

## 10. Construcción
Construir debe cambiar visualmente el mundo:
- materiales llegan;
- estructura se monta;
- piezas se encajan;
- luz y energía activan el edificio;
- cámara presenta el resultado;
- recompensa contextual;
- progreso persistente.

Nunca limitarse a descontar monedas y cambiar un número.

## 11. Raid / ataque
Un raid debe tener:
- objetivo;
- lectura de defensas;
- selección o impacto;
- destrucción/reacción;
- botín;
- riesgo;
- resultado;
- persistencia.

Debe existir espacio para escudos, contraataques, protección, modificadores y eventos.

## 12. Colección
Las cartas/arquetipos deben aportar:
- identidad;
- sets;
- efectos;
- rareza;
- narrativa;
- progreso;
- decisiones;
- futuras interacciones sociales.

Coleccionar no debe ser una pantalla de inventario vacía.

## 13. Economía
La economía se modela como sistema:
- fuentes;
- sumideros;
- ritmo;
- cap;
- catch-up;
- protección;
- recompensas;
- eventos;
- inflación;
- monetización.

La economía jamás debe sustituir a la diversión. Cada moneda tiene una función clara y un coste cognitivo mínimo.

## 14. Retención
Preparar métricas para:
- tutorial completion;
- primera sesión;
- D1/D7/D30;
- sesiones/día;
- duración;
- progresión;
- retorno por evento;
- conversión;
- ingresos;
- economía;
- churn;
- rendimiento técnico.

No optimizar métricas en abstracto: cada experimento debe declarar hipótesis, métrica primaria y riesgo.

## 15. LiveOps
Diseñar desde el inicio para:
- temporadas;
- eventos;
- misiones;
- recompensas;
- rotación;
- remote config;
- experimentos;
- contenido limitado;
- ofertas;
- comunicaciones;
- rollback.

## 16. Backend
Frontera prevista:
- autenticación;
- cloud save;
- perfil;
- inventario;
- economía;
- eventos;
- configuración remota;
- analytics;
- social;
- anti-cheat;
- validación server-authoritative para operaciones sensibles.

Offline-first significa jugable sin red cuando sea seguro, no confiar en el cliente para datos competitivos o económicos.

## 17. Arquitectura de contenido
Separar:
- reglas;
- datos;
- escenas;
- assets;
- UI;
- configuración;
- telemetría.

Un mundo nuevo debe poder añadirse de forma aditiva y con mínimo cambio de código.

## 18. Arte
La dirección visual debe buscar:
- siluetas reconocibles;
- materiales físicamente creíbles;
- lectura a pequeña escala;
- jerarquía;
- luz cinematográfica;
- colores por mundo;
- VFX con propósito;
- UI premium.

No llenar la pantalla de detalle sin jerarquía.

## 19. Audio
Preparar:
- diegetic ambience;
- UI;
- dados;
- pasos;
- impacto;
- construcción;
- raid;
- recompensa;
- música por mundo;
- stingers;
- mezcla dinámica;
- haptics sincronizados.

## 20. 3D
El estándar objetivo de presentación del personaje final requiere:
- malla 3D de producción;
- UV/materiales;
- rig;
- skinning;
- blendshapes o equivalentes faciales cuando proceda;
- animaciones de locomoción;
- idle;
- reacción;
- celebración;
- interacción;
- ataque;
- caída/impacto;
- cinemáticas.

Una imagen 2D no se presenta como sustituto de un personaje 3D de producción.

## 21. Pipeline de animación
Estados mínimos:
Idle, Anticipation, Roll, Travel, Land, Reward, Build, Attack, Raid, Shield, ChestOpen, Celebrate, Hurt, WorldTransition.

Cada estado debe tener:
- duración;
- interruptibilidad;
- prioridad;
- efectos;
- audio;
- cámara;
- salida.

## 22. Investor Demo
El Investor Demo debe demostrar en minutos:
- identidad;
- diversión;
- core loop;
- construcción;
- raid;
- colección;
- mundo;
- progresión;
- presentación premium;
- persistencia;
- arquitectura extensible.

No debe depender de texto explicativo para parecer más completo de lo que es.

## 23. QA
Puertas mínimas:
G0 Build reproducible
G1 Instalación limpia
G2 Lanzamiento estable
G3 Primera sesión
G4 Core loop
G5 Economía/persistencia
G6 Identidad DALMA
G7 Mundo/diferenciación
G8 Presentación premium
G9 Analytics/backend boundary
G10 Investor Demo
G11 Beta con evidencia.

“Compila” no significa “funciona”.
“Instala” no significa “está terminado”.

## 24. Android
Cadena obligatoria:
source → build reproducible → validación del APK → integridad/firma → instalación limpia → lanzamiento → smoke test → acciones reales → estabilidad → artifact exacto.

El artefacto entregado debe ser exactamente el que fue validado.

## 25. Seguridad
Producción:
- Play Integrity;
- validación server-side;
- secretos fuera del cliente;
- protección de economía;
- logs;
- control de fraude;
- recuperación;
- privacidad;
- mínimo privilegio.

## 26. Tamaño
El tamaño del APK no es un objetivo. Se busca:
- calidad;
- compresión;
- carga incremental;
- assets apropiados;
- distribución por bundle cuando proceda.

No se infla artificialmente el producto para aparentar profundidad.

## 27. IP y expansión
El juego debe poder extenderse a:
- coleccionables;
- merchandising;
- cortos;
- cine/serie;
- colaboraciones;
- experiencias;
- libros;
- eventos;
- otras plataformas.

La expansión debe nacer de una IP fuerte, no de añadir productos sin cohesión.

## 28. Atajos prohibidos
- APK placeholder;
- pantallas simuladas sin lógica;
- arte que tape un loop débil;
- afirmar pruebas no realizadas;
- inventar métricas;
- copiar IP protegida;
- usar “3D” cuando solo hay un sprite;
- confundir éxito de CI con éxito de producto;
- inflar tamaño;
- enviar un artefacto no verificado.

## 29. Principio de información
Cada ciclo de trabajo debe reducir incertidumbre o aumentar valor. Si una tarea solo genera movimiento, documentación o builds sin aportar evidencia, debe cuestionarse.

## 30. Equipo de referencia
Actuar como si existieran especialistas de:
game design, economy, UX, UI, 3D, character art, animation, VFX, audio, narrative, backend, mobile, QA, data science, analytics, UA, growth, LiveOps, security, IP, legal, localization y publishing.

Cuando un área exceda las capacidades del runtime actual, se modifica la arquitectura en vez de degradar el estándar.

## 31. Definición de terminado
No existe “terminado” cuando:
- solo instala;
- solo compila;
- solo luce bonito.

Está listo para la siguiente puerta cuando la evidencia correspondiente está presente.

## 32. Pregunta final
**¿Qué activo real hemos construido, qué evidencia tenemos de su potencial, qué riesgos permanecen y cuál es el siguiente paso de mayor valor?**
