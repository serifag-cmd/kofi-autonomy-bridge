# DALMA ADVENTURE — TOP 10 WORLD PRODUCT TARGET

## North Star

The product target is not "an installable APK" and not merely "a functional beta".

The target is a mobile game vertical slice designed from day one with the ambition to compete for a Top 10 global position in its category.

This is a product ambition, not a claim of current market position or future outcome.

## Investor Demo acceptance gate

An APK is not an Investor Demo candidate unless it demonstrates, in one continuous first-session experience:

1. Immediate DALMA identity and visual impact.
2. A legible core loop: spin/roll -> reward -> choice -> build -> raid/attack -> collection -> progression.
3. A world that feels authored rather than a renamed village.
4. A recognizable DALMA protagonist/IP presence.
5. Meaningful economy signals without menu overload.
6. High-quality motion, camera work, lighting, particles and audiovisual feedback.
7. Persistent progression and reliable local/offline behavior where appropriate.
8. Content architecture capable of adding worlds, buildings, cards, events, relics and characters without rewriting the game core.
9. Backend/cloud integration points for accounts, analytics, events, economy and live operations.
10. A repeatable Android build and verification pipeline.

## World design standard

Each world is a civilization with its own:

- architecture
- materials
- lighting language
- vegetation/environment
- creatures
- resources
- symbols
- hazards
- building language
- event mechanics
- narrative identity

Initial target worlds:

Genesis
Astral Wilds
Abyssal Ocean
Volcanic Crown
Neon Nexus
Shadow Dimension
Origin Core

## Visual standard

Visual quality is a core business requirement, not decoration.

The product should progressively move toward:

- authored DALMA characters
- high-quality environment art
- coherent VFX
- cinematic transitions
- responsive UI motion
- reward moments with strong anticipation and payoff
- readable map/city silhouettes
- distinctive world-specific construction
- optimized assets for mobile performance

APK size is a diagnostic signal, not a quota. Large size is justified only by real content such as art, animation, audio and world assets. Artificial padding is prohibited.

## Gameplay standard

The game must become fun before it becomes complex.

Every new system must improve one or more of:

- decisions
- anticipation
- reward
- mastery
- collection
- progression
- social interaction
- discovery

Avoid turning the game into a menu simulator.

## Technical direction

The current Expo/React Native implementation is acceptable as a functional bridge and product-validation surface, but the long-term game core must be evaluated against a dedicated game-engine architecture capable of sustained animation, effects, authored worlds, scalable content and mobile performance.

Replit is not part of the critical build or verification chain.

## Delivery levels

Test Técnico
- Build correctness and installability.

Investor Demo / Vertical Slice
- Functional loop + convincing visual/product experience + verification.

Release Candidate
- Production-grade build, services, signing, observability, live-ops readiness and final QA.

No lower-level artifact is to be presented as a higher-level delivery.
